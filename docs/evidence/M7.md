# M7 evidence

`VerificationIT`, with real processes end to end:

1. `scripts/capture-gnucobol.sh` compiles CardDemo's CBACT04C and the shipped TKDRIVER under GnuCOBOL 3.1.2 in Docker (`-std=ibm -fsign=EBCDIC`), loads real CardDemo records into indexed files with balances varied, and runs three scenarios. The bytes it writes are the expected results, in `testdata/captures/CBACT04C`.
2. `toolkit capture import` decodes them by the copybook layouts into 3 fixtures of 50 accounts and 50 transactions each.
3. `toolkit tests generate` writes JUnit 5 tests into a copy of the sample repository, and Maven compiles and runs them against `InterestCalculator`, a Java version written from the COBOL.

| Step | Result |
|---|---|
| Nothing registered | 3 of 3 fail. The only differences are TRAN-ORIG-TS and TRAN-PROC-TS, stamped at run time: every other field of every record matches |
| `toolkit tests report` | Those two fields become candidate deviations. Nothing is suppressed |
| Lead approves them, regenerate | 3 of 3 pass; `migration_status` reaches tests_passing with 3 of 3 |
| Break a rule: HALF_UP for COBOL's truncation | Fails, naming TRAN-AMT and ACCT-CURR-BAL, in all three runs |
| Approve a numeric tolerance on those fields | Passes: the approved deviation suppresses the known difference |
| A bigger change, /1000 for /1200 | Fails: outside the tolerance |

This also closes the M3b item "an approved deviation suppresses a known difference in a generated test".

## A real bug the harness found in CardDemo

My first Java posted interest for every account, and the harness failed on one field of one record. In `CBACT04C.cbl`, the `ELSE PERFORM 1050-UPDATE-ACCOUNT` at line 220 is unreachable: the `PERFORM UNTIL END-OF-FILE = 'Y'` at line 188 exits as soon as the read sets the flag. So **the last account's interest is written as a transaction but never added to its balance.** The reference reproduces this, with a comment, since characterization means matching behavior; fixing it would be a registered deviation.

## Decoder and layouts

`RecordCodecTest`: round trips for COMP-3, binary, signed zoned in cp037, cp1047 and ASCII overpunch; hand-built IBM bytes; OCCURS DEPENDING ON; REDEFINES; junk in a numeric field. Layout code against the compiler: `LENGTH OF` for 7 CardDemo records and a mixed-usage record (`W-PACK`, 39 bytes) all agree (`recordLengthsMatchWhatACobolCompilerComputes`).

## Limits, plainly

- This is GnuCOBOL, not z/OS. Character data is ASCII. It is the spec's "exported fixtures" path with honestly produced data, and the manifest says so.
- `ZoweCapture` is tested against a stand-in `zowe` executable, checking the commands and parsing. `FtpJesCapture` compiles and has had no server to talk to. **No capture has run against a real LPAR.**
- TKDRIVER really ran, under GnuCOBOL. It has not been compiled by Enterprise COBOL.
- CICS-bound programs use client-provided captures, per the spec.
